# 💰 스마트가계부

수입과 지출, 예산을 한눈에 관리하는 웹 가계부, 스마트가계부입니다. 외부 API 없이 동작합니다.

**🔗 데모: https://2026-bootcamp.vercel.app**

로그인 없이 누구나 볼 수 있는 읽기 전용 데모입니다. 보이는 데이터는 가상의 샘플이고, 접속한 날 기준 최근
6개월치로 만들어집니다. 저장·수정·삭제는 막혀 있습니다. (구성 방법은 아래 "Vercel 배포"의 "A. 공개 데모")

## 기능

| 화면 | 내용 |
| --- | --- |
| 메인 (`/`) | 월별 수입·지출·잔액, 전월 대비 지출, 월말 예상 지출, 예산 사용률, 카테고리별 지출 비율, 최근 6개월 추이 |
| 내역 (`/transactions`) | 검색, 수입/지출·카테고리·기간 필터, 거래별/카테고리별 보기, 수정·삭제·복사, CSV 내보내기 |
| 입력 (`/transactions/new`) | 수입/지출, 결제수단, 메모, 품목마다 카테고리 지정, 총액 자동 계산, 상호명 자동완성 |
| 달력 (`/calendar`) | 일별 수입·지출 합계, 날짜를 누르면 그날의 내역으로 이동 |
| 예산 (`/budget`) | 월 전체 예산과 카테고리별 예산 (80% 주의, 100% 초과 표시) |

## 기술 스택

Next.js 15 (App Router) · TypeScript · Tailwind CSS · Prisma + PostgreSQL(Neon) · Zod · Vitest

## 실행 (로컬 개발)

Node.js 22.12 이상이 필요합니다. 데이터베이스는 [Neon](https://neon.tech)의 무료 Postgres를 씁니다.
로컬 개발에는 **배포용과 다른 개발용 브랜치(데이터베이스)** 를 만들어 쓰세요. 같은 DB를 쓰면 개발 중 만든
테스트 데이터가 실제 데이터와 섞입니다.

```bash
npm install
cp .env.example .env     # DATABASE_URL 등을 채운다 (아래 환경 변수 표 참고)
npx prisma migrate dev   # 테이블 생성
npm run dev              # http://localhost:3000
npm test                 # 단위 테스트
```

로컬에서는 `APP_PASSWORD`와 `AUTH_SECRET`을 비워 두면 로그인 없이 쓸 수 있습니다.

> `npm run build`는 개발 서버를 끈 상태에서 실행하세요. 둘이 `.next` 폴더를 공유해 캐시가 꼬일 수 있습니다.

## 환경 변수

| 이름 | 설명 |
| --- | --- |
| `DATABASE_URL` | 앱이 쓰는 Postgres 연결 주소 (Neon의 풀링 주소) |
| `DATABASE_URL_UNPOOLED` | 마이그레이션이 쓰는 직접 연결 주소 |
| `APP_PASSWORD` | 사이트에 들어갈 때 입력하는 비밀번호 |
| `AUTH_SECRET` | 로그인 쿠키 서명용 비밀 값 (`openssl rand -base64 32`) |
| `DEMO_MODE` | `true`면 로그인 없는 읽기 전용 샘플 데모 (위 "공개 데모" 참고) |

## Vercel 배포

같은 저장소로 두 가지 방식의 배포를 만들 수 있습니다.

### A. 공개 데모 (누구나 구경하는 링크)

로그인 없이 누구나 볼 수 있는 **읽기 전용** 사이트입니다. 가상의 샘플 데이터를 보여 주고(접속한 날 기준
최근 6개월), 저장·수정·삭제는 막혀 있습니다. DB가 필요 없습니다.

1. 저장소를 GitHub에 올린다.
2. Vercel에서 **Add New → Project**로 그 저장소를 가져온다. Framework는 Next.js로 자동 인식된다.
3. **Environment Variables**에 `DEMO_MODE` = `true` 한 개만 추가한다.
4. **Deploy**를 누른다.

### B. 내 실제 가계부 (비밀번호 보호)

1. 위와 같이 저장소를 가져오되, **별도의 Vercel 프로젝트**로 만든다. (데모와 섞이지 않게)
2. **Storage** 탭에서 **Neon**을 연결한다. `DATABASE_URL`, `DATABASE_URL_UNPOOLED`가 자동으로 들어간다.
3. `APP_PASSWORD`, `AUTH_SECRET`을 추가한다.
4. 배포한다. 빌드 때 `vercel-build` 스크립트가 `prisma migrate deploy`로 테이블을 만든 뒤 앱을 빌드한다.

설정이 잘못되면 열어 두지 않고 막습니다(503). `APP_PASSWORD`/`AUTH_SECRET` 중 하나만 있거나, 데모 모드와
비밀번호를 함께 설정한 경우가 그렇습니다. 실제 가계부가 공개되는 설정 실수를 막기 위한 동작입니다.

## 설계 메모

- **총액은 입력받지 않습니다.** 품목 가격의 합계로 화면에서 자동 계산하고, 서버도 저장할 때 다시
  계산합니다. 클라이언트가 보낸 값은 믿지 않습니다.
- **카테고리는 품목 단위입니다.** 한 영수증에 식비와 생활용품이 섞여 있어도 카테고리별 통계가 정확합니다.
  카테고리 필터를 걸면 그 카테고리 품목만 남기고 합계도 다시 계산합니다.
- **수입/지출 카테고리는 서로 섞이지 않습니다.** 스키마(`superRefine`)가 거래 종류와 카테고리 불일치를 거절합니다.
- **통계는 DB가 아니라 순수 함수로 계산합니다.** 데이터 양이 개인 가계부 규모라 모든 거래를 읽어 메모리에서
  집계하며, 덕분에 계산 규칙을 DB 없이 단위 테스트할 수 있습니다. 데이터가 커지면 월 단위 조회·집계 쿼리로
  옮기는 지점이 `listTransactions`입니다.
- **월·필터는 URL 쿼리로 유지합니다.** 새로고침하거나 링크를 공유해도 같은 화면이 나오고, 메인 화면의
  카테고리나 달력의 날짜를 누르면 해당 조건의 내역으로 바로 이동합니다.
- **날짜는 로컬 시간 기준 문자열(YYYY-MM-DD)** 로 다룹니다. `toISOString()`은 UTC라 자정 무렵에
  하루가 어긋날 수 있어 쓰지 않습니다.
- **비밀번호 한 개로 앱 전체를 보호합니다.** 로그인하면 서명된 토큰을 `httpOnly` 쿠키에 담고, 미들웨어가
  화면과 API 요청을 모두 검사합니다. 서명 비교는 상수 시간 연산을 쓰고, `?next=` 로 돌아갈 경로는 같은 사이트
  안의 경로만 허용합니다(open redirect 방지).
- **설정 실수는 "열어 두는" 대신 "막는" 쪽으로 실패합니다.** 배포 환경에서 인증 환경 변수가 없으면 503을 돌려줍니다.
- **공개 데모는 DB가 아니라 코드에서 샘플을 만듭니다.** 실제 데이터와 섞일 일이 없고, 저장된 데이터가 없으니
  방문자가 망가뜨릴 것도 없습니다. 쓰기 API는 미들웨어가 403으로 막고, 데이터 계층에서도 한 번 더 막습니다.
- **한계:** 단일 사용자용 간이 인증입니다. 로그인 시도 횟수 제한은 틀렸을 때 지연을 두는 정도이고,
  여러 사용자나 계정 관리가 필요하면 Auth.js 같은 인증 라이브러리로 옮겨야 합니다.
